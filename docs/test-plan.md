## Affected Pages/Routes
- `#/` Queue (To listen) — search, save, confirmation row, Pick for me sheet, banners, toasts
- `#/listened` Queue (Listened) — sort by listenedAt, rating display
- `#/album/<id>` Album — Open, Mark as listened, rating/notes autosave, Delete + Undo, length entry
- Settings — music app, export (share/download/copy), import (pre-confirmation, errors), clear samples, erase all, diagnostics, version

## Key Interactions to Verify
- Search with fixtures: results match the latest text when an older reply resolves last (Queue)
- 503 then 200, 503 twice, timeout, offline, other HTTP error: each message keeps "Add it by hand" (Queue)
- Save, then edit during in-flight enrichment: both the edit and the enrichment survive (Album)
- Delete, Undo within 8 s; delete then re-add the same album during the window (Album, Queue)
- Two tabs: idle tab A, search in tab B completes; samples seeded once; one enrichment scheduler (Queue)
- Export on installed iPhone (share sheet; no-share fallback does not reset reminder) (Settings)
- Import own max-size export with CJK and newline-heavy text; failure on record N imports nothing (Settings)
- Schema bump with an old tab open shows the reload banner (any)
- Offline E2E against `vite preview` (not dev server): queue and saved covers render (Queue)

## Edge Cases
- Non-Latin titles (Cyrillic, Japanese, Korean, emoji-only) do not collide on normalization
  Value: protects=normalized identity keeps distinct non-Latin titles distinct; fails_when=punctuation stripping removes letters; why_new=no prior test; seam=none; no_claim=none beyond protects
- Same artist + title with two different MBIDs both save (Weezer)
  Value: protects=MBID decides identity when both sides have one; fails_when=artist+title check runs for MBID pairs; why_new=new rule; seam=none; no_claim=none beyond protects
- MusicBrainz values outside validator bounds (year 1899, 700 min, 600 tracks) export and re-import
  Value: protects=export/import round trip; fails_when=enrichment writes values the import validator rejects; why_new=new; seam=none; no_claim=real MusicBrainz data variety (fixtures)
- Imported dates with offsets and date-only values merge and sort correctly
  Value: protects=updatedAt merge ordering; fails_when=string comparison of mixed-offset ISO dates; why_new=new; seam=none; no_claim=device clock skew
- Hostile hosts in spotifyUrl/appleMusicUrl/coverUrl rejected on import and on enrichment
  Value: protects=link host allowlist; fails_when=any https host accepted; why_new=new; seam=none; no_claim=none beyond protects
- Duplicates inside one import file merge by the field rules
  Value: protects=one record per album after import; fails_when=within-file duplicates both insert; why_new=new; seam=none; no_claim=none beyond protects
- Query containing AND/OR/NOT ("Love AND Theft") is searched as words
  Value: protects=Lucene query escaping; fails_when=bare operators reach MusicBrainz; why_new=extends Lucene escaping test; seam=none; no_claim=MusicBrainz ranking quality
- Ctrl/Cmd+Z inside a text field performs native undo, not album Undo
  Value: protects=shortcut scoping; fails_when=global handler swallows text undo; why_new=new; seam=none; no_claim=none beyond protects
- Pick for me: 1,000 seeded runs never exceed the limit, never repeat back-to-back, every qualifying album appears, rough uniformity
  Value: protects=pick rules; fails_when=limit, no-repeat or eligibility logic regresses; why_new=assertions now stated; seam=random function parameter (also used by production for seeding none); no_claim=true randomness quality
